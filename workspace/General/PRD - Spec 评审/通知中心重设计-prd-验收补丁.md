## 2. 建议补充 2 条 BDD（Given / When / Then）

### BDD-补1：偏好保存反馈与应用内即时生效（覆盖 G1 / G2 / G3）

```gherkin
Feature: 通知偏好矩阵生效

  Scenario: 用户保存偏好后获得反馈且应用内立即生效
    Given 测试账号已登录，偏好矩阵初始为「系统全开；协作 应用内+推送 开、邮件 关；营销 仅应用内 开」
    And   应用内通知中心存在 1 条 marketing 未读
    When  用户在偏好页关闭「营销 · 应用内」并点击「保存」
    Then  偏好页出现明确成功反馈（toast：「偏好已保存，X 条已更新」或等价文案，不超过 2 秒）
    And   立即回到通知中心，营销分区已不再展示该条（无需刷新页面）

  Scenario Outline: 三类 × 三渠道矩阵可对称关闭
    Given 测试账号已登录
    When  用户关闭 <category> 的 <channel>
    And   触发一条 <category> 类型的通知投递到 <channel>
    Then  <channel> 不再投递该条（或发送日志标记 filtered_by_preference）
    And   该类其他渠道不受影响

    Examples:
      | category | channel   |
      | system   | push      |
      | collab   | email     |
      | marketing| push      |
      | marketing| email     |
```

### BDD-补2：默认进入时营销分区折叠 + 未读数实时刷新（覆盖 G4 / G5 / G6）

```gherkin
Feature: 通知中心默认视图与实时性

  Scenario: 默认进入通知中心时营销分区折叠且行动项可见标记
    Given 测试账号已登录，通知中心存在：协作 3 条（其中 1 条 requiresAction=true）、系统 2 条、营销 5 条
    When  用户首次进入通知中心
    Then  默认 Tab 为「全部」
    And   营销分区以"折叠/收起"形态呈现，标题旁显示未读数 5
    And   协作分区中 requiresAction=true 的那条带「待处理」视觉标记（标签/角标/色块 任一）

  Scenario: 新通知到达后分组未读数实时刷新
    Given 用户停留在通知中心「全部」视图
    When  系统推送 1 条新的 marketing 通知
    Then  营销分组的未读数在 ≤5 秒内从 5 变为 6，不需要手动刷新页面
```
